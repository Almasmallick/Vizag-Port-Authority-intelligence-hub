Fix 1 · "Full table" drawers

The tables get cut off with no hint to swipe

There are 8 tables, 440 to 960 px wide, on a 375 px screen. The right side is clipped, nothing says the table scrolls sideways, and once you swipe, the Year column scrolls away. You then see numbers with no row label.

Better solution

  • Keep the first column fixed (position: sticky; left: 0) with a solid background.
  • Fade the right edge while there is more to scroll, and remove the fade at the end.
  • Format numbers Indian-style: 1,905.15. Right-align them and use tabular numbers.
  • Show a "Swipe for more →" hint the first time a table opens.

Done when

  • At 375 px, the Year column stays visible while you swipe.
  • Every number has commas, and the digits line up in columns.
  • The fade appears on the right edge and goes away at the end.

    -webkit-mask-image: linear-gradient(90deg,#000 82%,transparent);
            mask-image: linear-gradient(90deg,#000 82%,transparent); }
  .drawer .scroll.at-end { -webkit-mask-image: none; mask-image: none; }

Fix 2 · Navigation

32 screens of scrolling with no way to jump

On a phone the page is 26,248 px tall. Finance alone is 5,700 px (7 screens) and "What is coming" is 5,400 px. There is no menu, so someone who wants the SWOT has to scroll through all of Finance to reach it.

Better solution

  • A 48 px sticky bar with one-word chips: Glance · Built · Finance · SWOT · Cargo · Rivals · Pulse · Coming · Research · Change.
  • It appears after the hero and stays hidden on the hero.
  • The active chip is filled with the ink colour and auto-scrolls into view.
  • Every section gets a scroll-margin-top of 56 px.

Done when

  • Every section can be reached in one tap from anywhere.
  • The active chip changes as you scroll.
  • Section headings never sit under the bar.
  • The bar clears the iPhone notch.
// SectionBar.tsx
const S = [['glance','Glance'],['understand','Built'],['finance','Finance'],['swot','SWOT'],
  ['explorer','Cargo'],['market','Rivals'],['pulse','Pulse'],['pipeline','Coming'],
  ['research','Research'],['next','Change']];
export function SectionBar() {
  const [active, setActive] = useState('');
  useEffect(() => {
    const io = new IntersectionObserver(es => es.forEach(e => e.isIntersecting && setActive(e.target.id)),
      { rootMargin: '-45% 0px -50% 0px' });
    S.forEach(([id]) => { const el = document.getElementById(id); el && io.observe(el); });
    return () => io.disconnect();
  }, []);
  useEffect(() => { document.querySelector(`.secbar a[href="#${active}"]`)
    ?.scrollIntoView({ inline: 'center', block: 'nearest' }); }, [active]);
  return <nav className="secbar" aria-label="Sections" hidden={!active}>
    {S.map(([id, l]) => <a key={id} href={`#${id}`} aria-current={active===id ? 'true' : undefined}>{l}</a>)}
  </nav>;
}

/* CSS */
.secbar { position: sticky; top: 0; z-index: 50; display: flex; gap: 6px; overflow-x: auto;
  scrollbar-width: none; padding: calc(6px + env(safe-area-inset-top)) 16px 6px;
  background: color-mix(in srgb, var(--paper) 92%, transparent); backdrop-filter: blur(8px); }
.secbar a { flex: none; min-height: 36px; padding: 0 12px; display: inline-flex; align-items: center;
  font-size: 14px; font-weight: 600; border: 1px solid var(--bar); color: inherit; text-decoration: none; }
.secbar a[aria-current] { background: var(--ink); color: var(--paper); border-color: var(--ink); }
section[id] { scroll-margin-top: 56px; }
@media (min-width: 1024px) { .secbar { display: none; } }

Fix 3 · "What is coming"

Seven screens of scrolling for eight short cards

#pipeline is 5,372 px tall and holds a sticky .pipeline-stage. On a phone you scroll through about 7 screens to read 8 cards, and the cards slide in sideways, so you see text cut off at the right edge while they move.

Better solution

  • Below 768 px, turn off the pin and the sticky stage. Keep them on desktop.
  • Show the 8 projects as a horizontal swipe row. Each card is 85% wide, uses scroll-snap-align: start, and the edge of the next card shows.
  • Keep the "01 / 08" counter you already have and update it on scroll.
  • No sideways slide-in animation on phones. Cards are simply there.

Done when

  • #pipeline is under 1,600 px tall at 375 px.
  • You can swipe through all 8 cards, and none show cut-off text.
  • The counter matches the visible card.

Fix 4 · Column charts

The bars grow from the middle and look broken

The live code animates [data-bar] with gsap.from({ scaleY: 0 }) but never sets transformOrigin. GSAP defaults to the centre, so while the animation runs, each bar grows out from its middle and floats above the axis. Until it ends, the chart looks like a bug, and the FY25 bar (the punchline, ₹1,314 crore) is always the last to appear.

Better solution

  • Bars grow from the axis: transformOrigin: 'center bottom'.
  • Draw FY25 first (or skip the stagger) so the headline number is never missing.
  • Value labels are at least 12 px. With 10 years on a phone, show the value only on FY16, FY20 and FY25, and the year under every bar.

Done when

  • During the animation, every bar touches the axis.
  • No chart text is smaller than 12 px.
  • With reduced motion turned on, the bars simply appear.
// choreography: the [data-bar] tween
gsap.from(bars, {
  scaleY: 0,
  transformOrigin: 'center bottom',   // was missing: bars grew from their middle
  duration: .45, stagger: { each: .04, from: 'end' },   // FY25 first
  ease: 'power2.out',
  scrollTrigger: { trigger: el, start: 'top 85%', once: true }
});

/* CSS */
@media (max-width: 767px) {
  .chart b, .chart span { font-size: 12px; }
  .chart [data-value]:not(:first-child):not(:last-child):not(:nth-child(5)) b { visibility: hidden; }
}

Fix 5 · "Where income comes from" / "Where money goes"

The percentage labels shrink to 4 px

The stacked bars put a percentage inside every segment. On a phone the small segments are 18–23 px wide, so the label is squeezed down to 4 px (measured on the live page). It looks like a smudge, and nobody can read it.

Better solution

  • Only print a label inside a segment that is at least 36 px wide. Otherwise, no label.
  • Labels inside segments are never smaller than 12 px.
  • Tapping a row shows all the shares as a list underneath it (Cargo 42% · Port and dock 30% · Rail 17% · Land 11%).
  • Put the legend above the bars, so you know the colours before you read them.

Done when

  • There is no text under 12 px anywhere in these charts.
  • Every share can be read by tapping its row.
// in the stacked-bar render
{segments.map(s => (
  <span data-stack-bar style={{ width: `${s.pct}%` }} key={s.key}>
    {s.pct >= 12 && <i>{Math.round(s.pct)}%</i>}   {/* ~36px at 300px track */}
  </span>
))}

/* CSS: never shrink to fit */
[data-stack-bar] i { font-size: 12px; font-style: normal; white-space: nowrap; }

Fix 6 · Scroll effects on phones

Twenty scroll-linked animations are heavy for a phone

The choreography file runs 20 scroll-linked tweens (scrub: .4): photo parallax, clip-path reveals on #finance, #research and #explorer, the timeline track and the hero video. Each one recalculates on every scroll frame. On a mid-range Android phone that adds up to choppy scrolling, extra battery drain and content that lags behind your finger.

Better solution

  • Keep scroll-linked effects for desktop: gsap.matchMedia() with (min-width: 768px) and (prefers-reduced-motion: no-preference).
  • On phones, keep only one-shot reveals (play once, under 0.5 s), and never start from opacity below 0.6.
  • Keep the hero video, which is the signature moment, but give it a poster frame.

Done when

  • Under 768 px, there are 0 ScrollTriggers with scrub except the hero (ScrollTrigger.getAll().filter(t => t.vars.scrub).length ≤ 1).
  • A Lighthouse mobile run shows Total Blocking Time under 200 ms.
const mm = gsap.matchMedia();
mm.add({
  desktop: '(min-width: 768px) and (prefers-reduced-motion: no-preference)',
  phone:   '(max-width: 767px) and (prefers-reduced-motion: no-preference)',
}, ({ conditions }) => {
  if (conditions.desktop) {
    // all scrub:.4 tweens: parallax, clipPath inset, globe circle, timeline track
  }
  // shared one-shot reveals (bars, rows) run for both
});
